Group Technology Reference Architecture

BKB-TECH-000 | Group Technology Reference Architecture

BKB Group standard

1\. Purpose and scope

Sets the Group's reference architecture: the layers every organisation's technology is placed on, how products are chosen for them, and the minimum security stack. Each organisation's technology-stack workbook (TSA-01 … TSA-42) records its own products against it.

2\. Architecture principles

Security is designed into each layer, not added at its edge. Identity is the control plane: every user, service and device is identified before access. Data is classified and protected where it is stored. Every capability has a named system owner and a GRC oversight role (Technology_Stack sheet).

3\. Capability model

The architecture has five layers. Each capability of an organisation's Technology_Stack sheet sits on the layer its Domain gives, below. A change, a risk or a control test names the layer of every system it touches, so the layer's owners are engaged.

| Layer | What it holds | Technology_Stack Domain(s) on it |
| :-: | :-: | :-: |
| Identity | Identity provider, IGA, PAM, PKI | Identity & access (IAM) |
| Data | Databases, data platforms, DLP, backup | Databases & data |
| Application | Business SaaS, ERP, HR, privacy and GRC tools | Business systems; Sector & core operations; GRC & compliance; AI platforms; DevSecOps & AppSec |
| Infrastructure | Cloud accounts, networks, endpoints, patching | Infrastructure & cloud; IT operations |
| Security operations | SIEM, EDR, case management, vulnerability tools | Security operations |
